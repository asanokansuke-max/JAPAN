# 統合申請アプリ（Google Apps Script）

早朝残業申請・代休申請・除雪申請を、Google Apps Script（GAS）の Web アプリ + Google スプレッドシート + Google Chat 通知で運用する社内申請システムです。
「開発要件書（2026年10月20日）」の第1段階・第2段階の内容（共通基盤、2種類＋除雪の申請、2段階承認、代理承認、総務課・社長への提出と受理、進捗確認、Chat 通知、テスト運用機能）を実装し、第3段階の一部（Chat 内の承認ボタン、リッチテキスト説明文、管理画面）も含みます。

## 全体像

```
利用者（PC / スマホ）
   │  Google Workspace アカウントで自動ログイン
   ▼
GAS Web アプリ（src/Index.html + Script.html）
   │  google.script.run
   ▼
GAS サーバー（src/*.gs）
   ├─ Google スプレッドシート …… 申請データ・マスター・履歴・設定
   └─ Google Chat ……………………… DM で承認依頼・進捗通知、カードのボタンで承認/却下/受理
```

### 承認の流れ

```
申請者 ─▶ 上長（申請者が候補から選択）─▶ 常務（または代理承認者）─▶ 総務課・社長へ提出 ─▶ 受理
            承認 / 却下                       承認 / 却下                 承認ではなく「受理を記録」
```

- 常務ステップの承認依頼は、常務と代理承認者（小林仁次）へ同時に届きます。どちらかが承認すればそのステップは完了し、重複承認はロックで防ぎます。誰が承認したかは履歴に残ります。
- 総務課・社長は承認者ではなく提出先です。承認・却下ボタンは出ず、「受理を記録する」だけが表示されます。
- 承認経路は「承認経路」シートで変更できます。承認ステップの行を増やせば 3 段階以上にも対応します。

### 申請者から見える状態

| 状態 | 表示 |
|---|---|
| 上長の承認待ち | 申請中（上長の承認待ち） |
| 常務の承認待ち | 上長承認済み（常務の承認待ち） |
| 最終承認済み（提出済み） | 最終承認済み・総務課・社長へ提出済み（受理待ち） |
| 受理済み | 受理済み |
| 却下 | 却下（却下理由を表示） |
| 取下げ | 取下げ（上長承認前のみ申請者が取下げ可能） |

## ファイル構成

| ファイル | 役割 |
|---|---|
| `appsscript.json` | マニフェスト（タイムゾーン、Web アプリ公開設定、スコープ、Chat アプリ設定） |
| `src/Config.gs` | シート名・役割名・状態コード・設定の既定値などの定数、設定の読み込み |
| `src/Setup.gs` | **初回に `setup()` を実行**するとシートと初期マスターを作成 |
| `src/Db.gs` | スプレッドシートを DB として読み書きするヘルパー（排他ロック付き） |
| `src/Users.gs` | 利用者・役割の判定（複数役割の兼任、本番/テスト環境の切り替え） |
| `src/RequestTypes.gs` | **申請種別ごとの入力項目・チェック・概要の定義**（新しい申請はここに追加） |
| `src/Descriptions.gs` | 申請ごとの説明文（HTML）の保存とサニタイズ |
| `src/Workflow.gs` | 申請・承認・却下・提出・受理・取下げの処理と一覧・詳細 |
| `src/Notify.gs` | Google Chat DM（サービスアカウント認証）/ Webhook / メールによる通知 |
| `src/ChatApp.gs` | Chat アプリのイベント処理（DM 登録、カードのボタン、却下ダイアログ） |
| `src/Api.gs` | 画面から呼び出す API（全関数でサーバー側の権限チェック） |
| `src/Admin.gs` | 管理画面（設定・マスター編集・説明文） |
| `src/WebApp.gs` | `doGet`（Web アプリの入口） |
| `src/Index.html` / `Style.html` / `Script.html` | 画面（PC・スマホ対応のシングルページアプリ） |

## スプレッドシートのシート

| シート | 内容 |
|---|---|
| 設定 | 運用モード、テスト通知先、Web アプリ URL、通知手段、受理の完了条件など |
| 利用者マスター | メールアドレス、氏名、部署（初回アクセス時に自動登録） |
| 役割マスター | 役割 × メールアドレス × 環境（本番/テスト/共通）。同じ人に複数の役割、同じアドレスを複数役割に登録可 |
| 申請種別マスター | 種別の有効/無効、表示順、名称 |
| 承認経路 | 申請種別ごとのステップ（順序・名前・承認/受理・役割・選択方式） |
| 申請説明文 | 申請ごとの注意事項（HTML、管理画面のエディタで編集） |
| 申請データ / 申請データ_TEST | 申請本体（テスト運用時は _TEST に保存） |
| 操作履歴 / 操作履歴_TEST | 申請・承認・却下・提出・受理・取下げの履歴 |
| Chat通知先 | メールアドレスと Chat の DM スペースの対応（自動登録） |
| システムログ | 通知失敗などのログ |

## セットアップ手順

### 1. スプレッドシートと Apps Script を作る

1. Google スプレッドシートを新規作成（例: 「統合申請アプリDB」）。
2. 「拡張機能 > Apps Script」でスクリプトエディタを開く。
3. `src/` 配下の各ファイルをエディタに作成して貼り付ける（`.gs` はスクリプト、`.html` は HTML ファイルとして同名で作成）。
   - clasp を使う場合: `.clasp.json.example` を `.clasp.json` にコピーしてスクリプト ID を入れ、`clasp push`。
4. 「プロジェクトの設定」で「appsscript.json マニフェストをエディタで表示する」を有効にし、`appsscript.json` の内容で置き換える。
5. エディタで `setup` 関数を選んで実行（初回は権限の承認が必要）。シートと初期マスターが作成される。

### 2. Web アプリとして公開する

1. 「デプロイ > 新しいデプロイ」 > 種類「ウェブアプリ」。
2. 次のユーザーとして実行: **自分（デプロイする人）**、アクセスできるユーザー: **組織内の全員**（Google Workspace のドメイン）。
3. 発行された URL を「設定」シートの `APP_URL` に貼る（Chat 通知のリンクに使われる）。
4. 利用者には URL を案内する。アクセスした人は利用者マスターに自動登録される。

### 3. Google Chat 通知を有効にする（推奨）

DM 通知と Chat 内の承認ボタンを使うには、この Apps Script を Chat アプリとして登録します。

1. Apps Script の「プロジェクトの設定」で Google Cloud プロジェクト（GCP）を標準プロジェクトに切り替える（プロジェクト番号を入力）。
2. GCP で **Google Chat API** を有効化し、「構成」タブで Chat アプリを設定する。
   - アプリ名・アバター・説明を入力
   - 機能: 「1:1 のメッセージを受信する」「スペースとグループの会話に参加する」を ON
   - 接続設定: **Apps Script プロジェクト** を選び、デプロイ ID を入力（「デプロイ > デプロイを管理」で確認。開発中は HEAD デプロイでも可）
   - 公開設定: 組織内の特定のユーザー／全員に公開
3. GCP で **サービスアカウント**を作成し、JSON キーをダウンロードする。
   - `Setup.gs` の `saveChatServiceAccountJson()` の `json` に JSON の中身を貼り付けて 1 回実行し、実行後に貼り付けた内容を消す（スクリプトプロパティ `CHAT_SERVICE_ACCOUNT_JSON` に保存される）。
   - このサービスアカウントは Chat アプリの「アプリ認証」として DM を送信するために使う（スコープ `chat.bot`）。
4. 各利用者は Google Chat でこのアプリを検索して DM を開き、何かメッセージ（例: 「こんにちは」）を送る。これで「Chat通知先」シートに DM スペースが自動登録され、以後の通知が DM で届く。
5. 管理画面「設定」の「自分宛てに通知テストを送る」で確認する。

Chat が未設定・未登録の相手には、設定 `NOTIFY_EMAIL_FALLBACK=TRUE` のときメールで通知します。`CHAT_WEBHOOK_URL` にスペースの着信 Webhook を設定すると、そのスペースへの投稿でも代替できます。

Chat のカードには「承認」「却下」「詳細を開く」（受理担当には「受理する」）のボタンが表示され、Chat 内で操作が完結します。却下はボタンを押すと理由入力のダイアログが開きます。

## テスト運用 → 本番運用

`setup()` 直後は **テスト運用（MODE=TEST）** です。

- 役割マスターには、環境=テストの行として全役割に `kobayashi.jinji@appx.co.jp` が登録されています。環境=本番の行は空欄・無効の状態で用意してあります。
- テスト中はすべての通知が `TEST_NOTIFY_EMAIL` に集約され、本文に「【テスト運用】本来の宛先: …」が付きます。実際の承認者には届きません。
- 申請データは `申請データ_TEST` / `操作履歴_TEST` に保存され、本番データと混ざりません。
- テスト中は同じ人が申請・承認・受理をすべて行えます（本番では自分の申請は自分で承認できません）。
- テスト対象者を変えたいときは、役割マスターのメールアドレスを入れ替えるだけです。

本番へ移行するとき:

1. 管理画面「役割マスター」で、環境=本番の行に実際の上長・常務・総務課・社長のメールアドレスを入れて有効=TRUE にする（代理承認者の行は環境=共通のまま）。
2. 「設定」で `MODE` を `PROD` に変更して保存する。
3. 通知テストで本番の宛先に届くことを確認する。

テストに戻すときは `MODE` を `TEST` に戻すだけです。

## 管理画面でできること

ホーム画面の「管理」（システム管理者の役割を持つ人、または管理者未登録時はスプレッドシートの所有者）から:

- **設定・運用モード**: MODE、通知先、受理の完了条件（ANY/ALL）、取下げの可否、早朝残業の終了時刻（始業時刻）など
- **役割マスター / 利用者マスター / 承認経路 / 申請種別 / Chat通知先**: 表形式でそのまま編集・保存（内容のチェック付き）
- **説明文（注意事項）**: 申請種別ごとにリッチテキスト（見出し・太字・文字色・箇条書き・リンク）で編集。保存するとすぐ申請画面に反映
- **全申請**: 現在のモードの全申請を閲覧

同じ内容はスプレッドシートを直接編集しても反映されます。

## 申請種別の追加方法

1. `src/RequestTypes.gs` に定義を追加する（`definitions['xxx'] = { id, name, formTitle, icon, fields, validate, summary }`）。
   項目タイプは `text / textarea / date / time / number / select / radio / static / group` です。
2. 「申請種別マスター」に行を追加する（種別ID・名称・有効・表示順）。管理画面からも追加できます。
3. 専用の承認経路が必要なら「承認経路」にその種別IDの行を追加する（無ければ既定経路 `*` が使われる）。
4. 管理画面「説明文」で注意事項を登録する。

画面・承認・通知・履歴は共通機能なので、種別を追加しても作り直しは不要です。

## 実装上の前提・要確認事項

要件書の「今後決定する事項」のうち、次は暫定的に決めて実装しています。必要に応じて設定・コードで変更できます。

- **早朝残業申請に「対象日」を追加**: GroupSession の画面には無いが、事後申請で日付が必要なため。開始時刻の終了側（8時20分）は設定 `EARLY_OT_END_TIME` で固定表示。昼休憩は 15 分単位の選択式、17:30〜17:45 の休憩は「取得した／していない／残業なし」の 3 択。
- **除雪申請の入力項目は仮**（実施日・場所・開始/終了時刻・作業者・備考）。GroupSession の稟議の項目を確認して `RequestTypes.gs` を調整してください。
- **申請の修正は不可、取下げは上長承認前のみ可**（設定 `ALLOW_WITHDRAW` で無効化可）。修正したい場合は取下げて再申請。
- **却下時は理由必須**で、申請者へ Chat/メールで通知。
- **受理の完了条件は ANY**（総務課・社長のいずれか 1 人が受理すれば完了）。`RECEIPT_RULE=ALL` で全員の受理を必須にできる。
- **代理承認者は常務ステップで常務と同じ権限**を持ち、常に同時通知される。
- **自分の申請を自分で承認することは本番では不可**（テストでは可）。管理者は例外として承認・受理操作が可能。
- 役割で決まるステップ（常務・総務課・社長）の担当者は承認時点の役割マスターから求めるため、役員交代はマスター変更だけで反映される。上長は申請時に選んだ人で固定。

## 動作確認

`src/*.gs` は Node.js 上でスプレッドシート等をモックしたテストで、申請→上長承認→常務承認→提出→受理、却下、取下げ、権限チェック、本番/テストのデータ分離、Chat カード操作、説明文のサニタイズを確認済みです。実際の Google Chat 連携（DM 送信・カードボタン）は Chat アプリの登録後に通知テストで確認してください。
